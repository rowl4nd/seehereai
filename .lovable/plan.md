
## Plan: Fix the blank screen and `useEffect` runtime crash

### Root cause
The app is very likely booting with an inconsistent dependency graph, not an app-level hook bug.

Three concrete issues stand out:
1. `package.json`, `package-lock.json`, and `bun.lock` disagree on key packages.
2. `react-day-picker@8.10.1` does not support `date-fns@4`, but `package.json` requests `^4.1.0`.
3. Vite is not explicitly deduping React, so a bad prebundle can cause `QueryClientProvider` to resolve hooks against the wrong React dispatcher and crash before the app renders.

### Implementation
1. **Normalize package versions in `package.json` to a compatible set**
   - Change `date-fns` from `^4.1.0` to a version supported by `react-day-picker@8.10.1` (`^3.6.0`).
   - Change `lucide-react` from `^1.8.0` to the working 0.x line already reflected in the older lockfile (`^0.462.0`).
   - Align `@lovable.dev/cloud-auth-js` to the actually installed modern version (`^1.1.1`) so the manifest matches the resolved package.
   - Leave `react` and `react-dom` on `18.3.1`.

2. **Harden Vite so React is always single-instanced**
   - Update `vite.config.ts` to add:
     - `resolve.dedupe: ["react", "react-dom"]`
     - `optimizeDeps.include: ["react", "react-dom", "@tanstack/react-query"]`
   - Keep the existing alias and plugin setup unchanged otherwise.

3. **Rebuild the dependency graph from one package manager**
   - Remove stale install artifacts and prebundles.
   - Reinstall dependencies cleanly so the lockfile and `node_modules` match the updated manifest.
   - Regenerate the chosen lockfile and avoid continuing with conflicting lock states.

4. **Verify the app boots before checking any feature pages**
   - Confirm `/` renders without a blank screen.
   - Confirm the runtime error no longer appears in the console.
   - Confirm `/credits` still loads and the checkout flow still works after the dependency cleanup.

### Files to update
- `package.json`
- `vite.config.ts`
- lockfile(s) generated by the clean reinstall

### What will not change
- No page styling
- No copy
- No auth flow behavior
- No checkout logic changes unless verification shows the credits page also regressed independently

### Technical notes
The crash location (`QueryClientProvider`) is a symptom, not the real bug. When React hooks resolve against a mismatched or duplicated React runtime, the first provider using hooks often explodes with `Cannot read properties of null (reading 'useEffect')`. The dependency drift plus unsupported `date-fns` major version is the strongest fix target.
